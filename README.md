# 电脑声音 → 手机

把电脑正在播放的声音，实时推到手机上播放。**电脑端是单文件 exe，手机端是 APK。**

- 支持 **USB 数据线**（走 `adb reverse` 隧道）或 **Wi-Fi 局域网**，断了会自动重建
- 两种编码：**Opus 压缩**（16~320 kbps，省带宽）和 **无损 PCM**（不压缩直传）
- 端到端延迟：有线上约 80~90 ms（不含手机自身输出通路）
- 电脑端缩到托盘后台运行；手机端有前台服务，锁屏/切后台不会被系统静音

---

## 用法

**只需要双击一个文件：`电脑声音.exe`**

它会自动：找 adb → 检查/安装手机端 App → 建 USB 隧道 → 拉起手机 App → 开始推流。
之后每 3 秒盯着 USB 状态，线拔了再插回来会自动重建隧道并把 App 拉回来。

首次使用前在手机上开「开发者选项 → USB 调试」，插上线，手机弹窗点允许。

不插线也能用：只要 adb 里能看到 Wi-Fi 设备（`adb connect 手机IP:5555`），程序会自动切到 Wi-Fi。

### 手机端界面

| 区块 | 说明 |
|---|---|
| 状态行 | 连接状态 / 走 USB 还是 Wi-Fi / 当前编码 |
| 诊断行 | `音轨积压 Xms（容量 Yms） 收到 N 帧/秒 网络积压 Zms` |
| 音量 | 100 级 |
| 缓冲 | 25 / 40 / 80 / 150 ms，越小延迟越低、越大越抗卡 |
| 编码 | Opus 压缩 / 无损 PCM |
| 码率 | 16~320 kbps（只对 Opus 有效） |

### 两端设置谁说了算

**电脑端是权威，手机端是遥控器。**

- 手机连上后一律以电脑端实际在发的为准，手机界面跟着刷新
- 手机上点按钮才会发命令去改电脑端，改完电脑端界面同步显示
- 在电脑端改任何参数会清掉手机的临时覆盖，以电脑端为准

## 延迟怎么看

界面上三个数字含义完全不同，很容易误判：

| 数字 | 含义 | 是否等于延迟 |
|---|---|---|
| **音轨积压** | AudioTrack 里真的存了多少还没播的音频 | **是**，这才是延迟 |
| 音轨容量 | AudioTrack 的 buffer 有多大（HAL 给的） | **不是**。水库容量不等于蓄水量 |
| 网络积压 | 排在 socket 里还没读走的数据 | 是 |

实测参考（蓝牙输出）：

```
音轨积压 20~30ms  (容量 440ms/蓝牙)   收到 100 帧/秒   网络积压 0ms
```

那 440ms 容量是荣耀在蓝牙路由下 `getMinBufferSize()` 给的值，**缩它会把蓝牙编码器饿死**
（听感发糊），所以蓝牙下特意不去动它。只要没被填满就不产生延迟。

**主要的固定延迟来自蓝牙 A2DP 本身（150~300 ms）**，在手机蓝牙协议栈和耳机固件里，
任何 App 都改不了。想确认就断开蓝牙用手机扬声器对比。

## 协议

TCP，端口默认 28700（另有 UDP 28701 做局域网发现广播 `PCAUDIO1 <port>`）。

**握手头（20 字节，小端）**

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | i32 | 魔数 `0x32414350`（"PCA2"） |
| 4 | i32 | 编码：0=PCM，1=Opus |
| 8 | i32 | 采样率 |
| 12 | i16 | 声道数 |
| 14 | i16 | 位深（固定 16） |
| 16 | i32 | Opus 码率 kbps（PCM 为 0） |

**数据**：每帧固定 **10ms** 音频。Opus 帧前面加 2 字节小端长度；PCM 直接裸流。
48000Hz 下 10ms = 480 采样点，所以**每秒必须正好 100 帧**。

**反向控制（手机 → 电脑）**，每条 3 字节 `op + u16`：

| op | 含义 |
|---|---|
| 0x01 | 改 Opus 码率 |
| 0x02 | 改声道数 |
| 0x03 | 改编码（0=PCM, 1=Opus） |
| 0x04 | 改无损采样率（44100/48000） |

## 踩过的坑（都是实测出来的，不是推测）

### 1. 音频帧率不是视频帧率，必须是精确的 100/秒

每帧装 10ms 音频，所以每秒必须送 100 帧 —— 这是「实时」的定义，不是可选的流畅度档位。

原实现用 `Thread.Sleep(3)` 轮询补静音帧。但 **Windows 的 `Thread.Sleep` 最小粒度是 15.6ms**，
而且这台机器上 `timeBeginPeriod(1)` 已经失效（实测 `Sleep(1)` 仍要 15.55ms）。结果：

| | 修复前 | 修复后 |
|---|---|---|
| 电脑静音时 | **59.9 帧/秒**（慢 40%，手机必然饿死） | 98.9 |
| 电脑正在放声 | **113.7 帧/秒**（快 14%，延迟越积越大） | 99.9 |

改用 `CreateWaitableTimerExW` + `CREATE_WAITABLE_TIMER_HIGH_RESOLUTION`（实测周期 10.3ms），
配合绝对墙钟对齐、只补欠下的帧、**绝不清零**。

### 2. 电脑静音时 WASAPI 环回一个字节都不产

不是给静音数据，是 `BytesRecorded == 0`。所以必须自己补静音帧，否则手机读超时 →
断开 → 重连，无限循环。

### 3. WASAPI 环回是一次给 50~70ms 的数据（一阵一阵的）

直接转发的话手机得为了扛突发把缓冲开很大。加了抖动缓冲：采集侧只负责切帧+编码，
由节拍器按墙钟一帧一帧均匀发出。

### 4. 蓝牙要单独一套参数

蓝牙链路固有延迟 100~300ms，还多一层重采样+编码。原来不分路由地压缓冲到 25ms、
还要求 `PERFORMANCE_MODE_LOW_LATENCY`，等于把 BT 编码器饿死，听感发糊。
现在按路由分开：蓝牙给足缓冲（60ms 预启）、不要求低延迟、不缩缓冲。

### 5. 阻塞式 `AudioTrack.write()` 能把整条链路拖死

音频通路被系统掐住时（后台管控、HAL 卡住），阻塞写会**永久阻塞**，接收循环跟着卡死 ——
现象是「socket 还连着、服务端还在发，但没声音也不重连」。改非阻塞写，满了丢这一小段。

### 6. 荣耀会静音后台播放

logcat 抓到实锤：

```
AudioHardening background playback would be muted for com.dsh.pcaudio
```

一退到后台/锁屏就没声音，而 socket 还是好的。加 `foregroundServiceType="mediaPlayback"`
的前台服务解决。

### 7. 改设置必须「先发出去、再断开」

改编码要重连才生效。原实现先丢后台线程写命令、调用方紧接着 `close()` socket ——
命令根本没发出去 → 电脑端设置没变 → 下次握手又不一致 → **无限快速重连**。
现在命令真正写出并 flush 完再断，另加 3 次上限保险。

### 8. USB 隧道掉了会静默退化成 Wi-Fi

`adb reverse` 被 adbd 重启冲掉后，App 会撞一次 127.0.0.1 失败再退回 Wi-Fi。
现在：只有最后一个候选失败才算「断开」，切换会明说，而且程序常驻盯着 USB 状态、
隧道没了自动重建并把 App 拉回来。

### 9. 排查工具本身也会骗人

- `PowerShell` 读 UTF-8 无 BOM 的 `.ps1` 会按 GBK 解码 → 中文字符串直接语法错误
- `Get-Content` 读 UTF-8 文件会显示成乱码，让人误判「源码编码坏了」（其实没坏）
- 函数名 `Del` 会被 PowerShell 的 `del` 别名（= `Remove-Item`）抢先，得换名字
- 荣耀把第三方应用的 logcat 全吞了（连 `Log.w` 都看不到），所以关键诊断做进了界面

## 自己编译

```powershell
# 电脑端
powershell -ExecutionPolicy Bypass -File tools\build-server.ps1

# 手机端（借 Unity 自带的 Android SDK/JDK，不需要 Gradle、不联网）
powershell -ExecutionPolicy Bypass -File tools\build-apk.ps1

# 出发布包（独立单文件 exe + APK + adb + 源码）
powershell -ExecutionPolicy Bypass -File tools\make-release.ps1
```

依赖：.NET 9 SDK；编译 APK 需要 `D:\Unity\2023.1.22f1\...\AndroidPlayer`
（路径写在 `tools/build-apk.ps1` 顶部，可改）。

### 已知取舍

- MP3/AAC 之类没做：Android 与 PC 两边都要自带编码器，Opus 已经足够好，无损 PCM 是更直接的兜底
- 手机端 targetSdk 33：够用，且避免了新版本更严的前台服务限制
- keystore 提交在仓库里（密码 `pcaudio`）：自签名、只为保证能覆盖安装，不是需要保密的凭据
